# Post-fix full-profile Kubernetes diagnostic preparation

This package is preparation only and is execution-blocked pending the separate immutable check. It contains no evaluator source or executable binary,
VM operation, corpus invocation, result archive, or durable claim. The packaged
cloud transport is the reviewed task-scoped module only; it is not invoked during
preparation. The source and binary identities are pinned to the completed Linux correctness/build evidence. The pending immutable-check result must be recorded before any execution; no placeholder check hash is accepted.

The request is exactly one cache-OFF Kubernetes snapshot with profile `full`,
worker 1, trial 0, diagnostic scenario, and no ON arm, comparison, admission,
or retry. The product request deadline remains 120 seconds. The outer remote
controller timeout only allows collection and upload to finish.

The evaluator receives `ENTIRE_GRAPH_EXTRACTION_CORPUS_PHASE_BREADCRUMBS=1`.
The collector captures the evaluator's inherited stderr/stdout stream as
`process.log`; phase breadcrumbs are evidence for timeout localization and are
not comparative timing data.

A captured result is always `captured_unreviewed` with `admission_eligible=false`
and `no_performance_claim=true`. Complete diagnostics arrays, observation and
diagnostics identities, raw compact-array digests, before/after input identity,
process metadata, claim ledger, logs, and transport records are retained. A
missing artifact, timeout, identity mismatch, or incomplete diagnostics is an
`issue` and cannot be promoted or retried.
