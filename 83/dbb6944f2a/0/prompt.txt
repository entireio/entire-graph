QUESTION 1 — symlinks become SCIP Documents.
Every FileRecord becomes a scippb.Document. FileRecord has no mode field.
internal/gitutil/git.go ListFiles uses `git ls-tree -r -z --name-only <rev>`, no mode
filter, so committed-tree snapshots include symlinks (mode 120000) as if regular files.
The worktree path DOES skip symlinks (internal/sem/provider.go ~9970: info.Mode()&fs.ModeSymlink).
SCIP requires Document.relative_path to identify a regular file.
Where should this be fixed?
 (a) gitutil.ListFiles — filter non-blob modes. Correct at the source, but changes ALL
     committed-tree snapshots (NDJSON, compact, cache keys), far beyond the SCIP export.
 (b) SCIP encoder only — but it cannot currently tell a symlink from a regular file.
 (c) something else.
What is the smallest correct fix, and what is the blast radius of (a)?

QUESTION 2 — no aggregate memory guard on the SCIP encoder.
A SCIP Index is one protobuf message and cannot be streamed, so the encoder retains all
files/symbols/externals/relations, then builds a second complete protobuf and marshals it.
Measured ~1.5x peak RSS vs the streaming ndjson encoder on a 28MB-NDJSON repo.
There is no aggregate cap. The stderr JSON "omission note" is written by the CLI AFTER
StreamSnapshot returns, so if the encoder returns an error the note is never written.
What is the right bounded-failure design? Options I see: cap retained entity count and
fail fast with a clear error (no note); restructure so the note is emitted on that error;
or emit a truncated-but-valid index (seems bad: silently partial). Which, and why?
