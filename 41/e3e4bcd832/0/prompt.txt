readLimitedFile writes limitedUnaddressable and limitedUnavailable without readOutcomeMu, while other workers lock those same maps. Concurrent map writes can abort the dependents scan.

processChangedFile never sets scan.stopped or calls overBudget, so the reducer cannot end a window at the same index the sequential loop would have. Budget warnings therefore name different files, and up to a full prime window is parsed after the deadline.

This can substantially exceed the requested budget and omits the required skipped-file warnings for work started after the deadline; check `overBudget()` inside `processChangedFile` and return a stopped scan.

**Location:** `internal/sem/dependents.go:428`
