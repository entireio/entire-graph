### Findings

**1. `/Users/thomi/Projects/entire-graph/internal/cli/agents.go:191` — medium.** The HTML-comment scan (`&lt;!--` / `--&gt;`) runs *before* the fence-state check at line 194, so a bare `--&gt;` anywhere in `CLAUDE.md` — including inside a fenced code block — hits `return false, nil` and aborts detection, discarding an `@AGENTS.md` import that was already found on an earlier line. Verified: `"@AGENTS.md\n\nFlow: a --&gt; b\n"` → `false`, and ```` "```text\nlocate --&gt; entire graph search\n```\n@AGENTS.md\n" ```` → `false`. A mermaid diagram (`A --&gt; B`) or an ASCII arrow in prose is extremely common in agent instruction files, so the new normalization silently no-ops for a large share of the repos it targets. Same ordering also lets an unterminated `&lt;!--` inside a fence swallow the closing fence line. Fix: evaluate `fence` state before comment scanning, and return `found` rather than `false` when the arrow appears after the import.

**2. `/Users/thomi/Projects/entire-graph/internal/cli/agents.go:142` — low/medium.** The replacement block is a single HTML comment: `&lt;!-- Entire Graph instructions are inherited through AGENTS.md. --&gt;`. Before this change, even a tool that reads `CLAUDE.md` but does not resolve Claude's `@` import syntax still saw the prose ("This repo has the entire-graph code graph installed… read `.entire/graph-agent.md`") and could act on it; now it sees a comment and the `@AGENTS.md` line it also cannot follow. Consider making the notice a visible sentence that names `AGENTS.md` and `.entire/graph-agent.md` in plain text. Related stale docs that now overstate the behavior: `/Users/thomi/Projects/entire-graph/README.md:25` ("drops the operating guide into your project's `AGENTS.md` and `CLAUDE.md`… any agent that reads those files"), `/Users/thomi/Projects/entire-graph/internal/cli/help.go:71` (`long:` "Writes the operating guide into a project's AGENTS.md and CLAUDE.md"), and `/Users/thomi/Projects/entire-graph/docs/readme-plan.md:149` ("`init-agents` writes the same pointer block to both files").
